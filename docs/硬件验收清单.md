# 真机验收清单

在你自己的局域网里做。每一步都由你触发。默认的 `smoke` 不会改坐标。不要把本文件里的空结果填成“已通过”。

开始前：

- [ ] 手机已解锁，并且由你在手机上打开开发者模式
- [ ] 第一次信任用数据线完成，信任提示由你亲手确认
- [ ] `ios-wifi-loc pair-guide` 里的 USB 命令由你自己执行，而不是由自动化执行
- [ ] 拔线后，手机和运行本工具的主机在同一局域网
- [ ] `ios-wifi-loc doctor` 的 `machine`、上游版本和 `developer dvt simulate-location set --help` 已看过
- [ ] `ios-wifi-loc devices` 能看到 Wi-Fi 设备，或你改用 `select --transport mobdev2 --host <局域网地址>`
- [ ] 已 `select --udid <那一台>`。有多台时必须写明，工具不会自动挑

演练（不改坐标）：

- [ ] `ios-wifi-loc smoke --profile ios17 --latitude <纬度> --longitude <经度>` 输出“未调用上游，未修改定位”
- [ ] 若系统版本低于 17，把 `ios17` 换成 `pre17`。读不到版本时不要用 `auto` 做演练

真机（会改这台手机的开发者定位）：

- [ ] 再次写出坐标，并加上 `--execute --i-understand-this-sets-a-real-device`
- [ ] 手机上的地图或系统定位显示接近你输入的坐标
- [ ] `ios-wifi-loc status` 在 iOS 17+ 上显示持有进程仍在。这仍要和手机屏幕互相核对
- [ ] 关掉 Wi-Fi 或离开局域网后，`ios-wifi-loc reconnect --attempts 3` 给出找不到设备的原因，并且没有改坐标
- [ ] 恢复网络后，不带 `--resume` 的 reconnect 只报告重新看到设备
- [ ] `ios-wifi-loc clear --profile <pre17|ios17>` 的返回码为 0，并且手机恢复真实位置
- [ ] 若 clear 失败，保留工具的原句“不能确认已经恢复真实定位”，不要手改成成功

下面三项这次开发没有做，清单里也不要勾成成功：

- [ ] OpenWrt 根文件系统里完成安装
- [ ] NanoPi R4S 上的实际系统完成安装
- [ ] GL.iNet XE300 128MB/MIPS 单机运行

验收时不要粘贴配对 plist、证书、私钥或 `ios-wifi-loc` 状态目录。UDID 只要在你自己的屏幕上使用即可。

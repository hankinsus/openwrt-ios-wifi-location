# 上游依据

记录日期：2026-11-25。下面只写当天打开过的页面和将要由本机 CLI 帮助复核的内容。没有把 iOS Simulator、旧笔记或未安装的二进制写成支持矩阵。

## 使用的上游

- 项目：<https://github.com/doronz88/pymobiledevice3>
- 发布页：<https://pypi.org/pypi/pymobiledevice3/json>
- 当天读到的版本：`11.63.1`
- 当天读到的 Python 要求：`>=3.9`
- 许可证：`GPL-3.0-or-later`。本仓库不附带它的源码，只在运行时调用它的命令。
- 文档入口：<https://doronz88.github.io/pymobiledevice3/latest/>

本工具固定调用这些已在文档和 `v11.63.1` 源码里出现的命令：

| 目的 | 命令 |
| --- | --- |
| Wi-Fi / USB 标识 | `usbmux list --network --simple` 和 `usbmux list --usb --simple` |
| 局域网公告（只记录原文，不假装解析成已配对设备） | `bonjour mobdev2` |
| 可隧道设备公告 | `remote browse --timeout <秒>` |
| 读取版本 | `lockdown info` |
| iOS 17 以下定位 | `developer simulate-location set/clear` |
| iOS 17 及以上定位 | `developer dvt simulate-location set/clear` |

`v11.63.1` 的 `cli_common.py` 写明：

- `--mobdev2` 是布尔开关，用来做 bonjour/mobdev2 发现。
- `--mobdev2-host` 和 `--mobdev2` 不能同时用。
- `--usbmux` 需要套接字地址，不能空着传，否则会吃掉下一个参数。
- `--remotepairing` 是布尔开关。
- `--udid` 指定设备。多台设备时上游可能进入交互选择；本工具始终自己传入 `--udid`。

## 版本和隧道

来源：<https://doronz88.github.io/pymobiledevice3/latest/guides/ios17-tunnels/> 和开发者命令文档。

- iOS 17.0 起，开发者服务（含定位模拟）走 RSD 隧道。
- 文档中的默认路径是命令自己建立的、不需要 root 的用户态隧道。
- 同一页写明：iOS 17.4 及以上在 Linux 上可以不使用 root；iOS 17.0–17.3 在 Linux/Windows 上需要 `tunneld`。
- 本工具不执行 `remote tunneld`、`remote start-tunnel` 或 `lockdown start-tunnel`，因为那会创建隧道接口。17.0–17.3 因此默认拒绝。
- `developer dvt simulate-location set` 的文档写明会话保持到 Ctrl+C。`developer simulate-location set` 写明用于 17 以下，并保持到 `clear`。

这些句子描述的是上游文档，不是本仓库的真机结果。

## 无线和第一次配对

来源：同一隧道文档，以及 <https://doronz88.github.io/pymobiledevice3/latest/cli/remote/>、lockdown 命令文档。

- `lockdown wifi-connections on` 被写成插着 USB 做一次。之后 macOS 可以继续无额外参数；文档同时写明 Linux 自带 usbmuxd 发现不了 Wi-Fi 设备，这时用 `bonjour mobdev2` 和 `--mobdev2`。
- `lockdown remotepairing --pair` 被写成经过已经信任的 USB lockdownd，用来生成 RemotePairing 记录。
- `remote pair` 被写成给会显示 PIN 的设备（文档举例 Apple TV）。普通 iOS 设备通常不需要。
- `remote pair-host` 被写成 iOS 27+、由手机在“设置 → 开发者 → 已配对的 Mac”里发起。这只是文档句子。安装后的 `--help` 是否仍有这个子命令，由 `scripts/verify_upstream_help.py` 记录；没有手机实验。

配对产生的 `remote_*.plist`、证书和私钥不属于本工具的输出，也不会进入 git。

## 2026-11-25 在本开发机上的命令复核

机器是 Linux x86_64，Python 3.12.3。用 pip 安装了 PyPI 上的 `pymobiledevice3==11.63.1` 之后，实际执行了帮助命令，原始输出在 `docs/evidence/upstream-help-linux-x86_64/`。

- `pymobiledevice3 version` 打印 `11.63.1`，退出码 0。同一个二进制的 `--version` 退出码是 2，所以诊断使用 `version` 子命令。
- `developer dvt simulate-location set --help` 退出码 0，正文包含 latitude、longitude，以及 “keeping the session open until interrupted (Ctrl+C)”。同一页列出 `--udid`、`--remotepairing`、`--mobdev2`、`--mobdev2-host`。`--usbmux` 的说明是 usbmuxd 地址，不是布尔开关。
- `developer simulate-location set --help`、`usbmux list --help`（含 `--network` 和 `--simple`）、`bonjour mobdev2 --help`、`remote browse --help`、`lockdown info --help`、`lockdown wifi-connections --help`、`lockdown remotepairing --help` 都退出码 0。
- `remote pair-host --help` 退出码 0。帮助第一句是 “Advertise as a pairable host and accept a device-initiated pairing (iOS 27+).”。这只证明 11.63.1 的命令帮助里有这句话，没有手机配对实验。
- 本机没有 `/var/run/usbmuxd`。`usbmux list --network --simple` 退出码 1，日志是 “Failed to connect to usbmuxd socket. Make sure it's running.”。这不是“没有手机”以外的定位结论。

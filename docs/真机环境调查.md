# 真机环境调查

调查日期：2026-11-25。没有注册、订阅或付费，也没有连接任何 iPhone。

## 本代理能看到的机器

调用 Cursor 的 self-hosted worker 列表（个人和团队范围，最多 100 条）后，返回：

- `pools: []`
- `workers: []`
- `totalCount: 0`

没有正在连接的私有 worker，因此没有用户自己的测试机可以交给这次运行。开发机本身是 Linux x86_64 云虚拟机，没有接上 iPhone。

## GitHub 公共 runner

依据：<https://docs.github.com/en/actions/reference/runners/github-hosted-runners>

公开仓库的标准 runner 是 GitHub 托管的虚拟机。文档表格里有 Linux x64、Linux arm64 和 macOS arm64/Intel 标签，例如 `ubuntu-24.04`、`ubuntu-24.04-arm`、`macos-latest`。表格没有物理 iPhone。公开仓库使用这些标准 runner 不另外计费。

本仓库的 `.github/workflows/ci.yml` 使用其中三个标签，并在日志里写明 `physical_iphone=false` 和 `simulator_started=false`。macOS runner 即使镜像里带有 Xcode，也不能把 Simulator 当成已配对的手机；工作流不会启动 Simulator，也不会用它声称 Wi-Fi 定位或 RSD 隧道可用。

`ubuntu-24.04-arm` 只接近 R4S 的 CPU 位数。它是带 glibc 的 Ubuntu，内存远大于 128MB，不是 OpenWrt，更不是 XE300。

## 公开的真机服务

查过的页面都要求账号、套餐或你自己的设备实验室。没有找到一个免费、并且已经授权给这次运行、还能开放配对信任、开发者模式、usbmux/RSD 和主机网络的 iPhone。

| 页面 | 公开说明 | 这次为什么不用 |
| --- | --- | --- |
| [Sauce Labs Real Device Access API](https://docs.saucelabs.com/mobile-apps/real-device-access-api/connect-adb-and-xcode-to-remote-devices/) | 企业方案。低层 usbmux 只给 private devices；public device 不返回 `usbmuxdUrl`。iOS 17+ 上该隧道不承载 RemoteXPC，Xcode 集成不可用。 | 要付费账号。公共设备没有所需通道。未注册。 |
| [BrowserStack device tunneling](https://www.browserstack.com/docs/custom-device-lab/app-automate/appium/device-tunneling/ios-set-up) | 这是自有设备实验室的 Appium 隧道，要在你自己的电脑上管理 usbmuxd。 | 不是他们机房里一台免费公开手机。未注册。 |
| [AWS Device Farm 开发者指南](https://docs.aws.amazon.com/devicefarm/latest/developerguide/welcome.html) | 远程访问是浏览器里操作设备，或走托管的 Appium。 | 指南的远程访问描述没有把主机上的 usbmux/RSD/开发者配对交给客户。服务收费。未注册。 |
| [Firebase Test Lab for iOS](https://firebase.google.com/docs/test-lab/ios/get-started) | 在 Google 托管设备上跑应用的 XCTest。页面写明该产品将于 2027-09-30 关闭。 | 这是应用测试，不是 lockdown/usbmux。未注册。 |

因此没有可用的授权真机。代码和模拟进程测试继续。真机冒烟留在 `ios-wifi-loc smoke`：默认只打印将要执行的命令；改坐标必须同时给出 `--execute`、`--i-understand-this-sets-a-real-device` 和明确的经纬度。

## 定位实际怎么做

`MapSelectionView.locationUpdateCode` 调用 `simulate_location(deviceIP, latitude, longitude, pairingFilePath)`。

`IdeviceFFIBridge.swift` 里的 `simulate_location` 依次：

1. 若已有句柄，调用 `location_simulation_set`。
2. 否则用 IPv4 地址和 `RemotePairingPortResolver.resolve` 得到的端口。
3. `rp_pairing_file_read` 读取配对文件。
4. `tunnel_create_rppairing`。头文件写明 iOS 上这一调用同时完成配对校验和隧道。
5. `remote_server_connect_rsd`。
6. `location_simulation_new` 然后 `location_simulation_set`。

这些 C 原型在同一提交的 `idevice.h` 里核对过：`location_simulation_set`、`location_simulation_clear`、`location_simulation_new`、`rp_pairing_file_read`、`tunnel_create_rppairing`、`remote_server_connect_rsd`。

失败码在同一文件：1 地址、2 配对文件、3 隧道、9 远程服务、10 建立定位服务、11 设置、12 清除失败或没有会话。返回 0 只表示调用没有报错。源码没有把手机当前坐标读回来。

`clear_simulated_location` 在没有会话时直接返回 12。所以上游的“停止”也可能失败，不能写成已经恢复真实定位。

模拟开始后，`LocationSimulationSession.startResending` 用 `Timer(timeInterval: 4, repeats: true)` 再发坐标，并调用后台音频和后台定位。`MapSelectionView` 另外申请一个有限的 `UIApplication` 后台任务。`BackgroundLocationManager` 把 `desiredAccuracy` 设为 `kCLLocationAccuracyThreeKilometers`，文件末尾注释写明定位失败也可以，管理器只要在跑。这不是永久后台定位。系统可以结束后台任务。本改编没有复制这套保活。

## 配对

同一提交的 `PAIRING.md` 写了两条，本仓库没有在设备上执行：

- 方法 1：文档写 iOS/iPadOS 27 或更新时，应用可以自己生成配对文件，不需要电脑。`OnDevicePairingView.swift` 页脚写的是同一句：被配对的 iPhone 或 iPad 必须运行 iOS 或 iPadOS 27 或更新。
- 方法 2：电脑上的 iloader。文档写需要电脑和数据线；设备已经无线出现在 iloader 里时，文档说也可以。

上游 `OnDevicePairingService.swift` 里仅有的两处 `#available(iOS 27.0, *)` 在第 72 行和第 92 行。第 72 行只包住通知权限，第 92 行只包住后台音频和后台定位。`runPairing` 在这两处检查之外被调用。27 这个门槛来自 `PAIRING.md` 和界面文案，不是来自那两行编译条件。

本改编把 `performPairing` 的调用顺序放进默认目标的 `App/OnDevicePairingService.swift`，主机名改为 LanLocation，并去掉后台音频和后台定位保活。普通路径是导入配对文件，或走这条本机配对。手填路径只在高级区。配对文件写入 Application Support，模式 0600，完整文件保护，并排除备份。内容不显示、不进 git。这两条配对都没有在真机上执行。

## VPN 和 DDI

`DeviceConnectionContext.defaultTargetIPAddress` 是 `10.7.0.1`。README 要求打开 LocalDevVPN 一类回环 VPN，并提示心跳错误时检查 VPN 和 Wi-Fi。没有在真机上和其他 VPN 对比，所以不能说它们一定冲突或一定不冲突。

定位失败文案要求 DDI 已挂载。`DeveloperDiskImageService` 在系统主版本大于 26，或主版本为 26 且次版本至少为 4 时选择 cryptex 镜像，否则选择 personalized 镜像。这是源码分支，没有在设备上验证。

## 收进默认目标的部分

`LanLocation.xcodeproj` 直接编译这些文件，不需要再手工把 Swift 文件加进目标：界面、`DeviceLink.swift`、配对存储、本机配对服务、端口发现、磁盘镜像下载。构建阶段先跑 `scripts/fetch-idevice.sh`。没有返回 -50 的假端口。

前台每 4 秒重发一次已经确认的坐标。进程重启不会自动重发。收藏写入 `LanLocation/favorites.json`，和配对文件分开。

## 裁掉的部分

JIT、脚本、进程终止、安装应用列表、控制台日志、描述文件管理、地图检索、路线播放、后台音频和后台定位保活。没有复制上游的 macOS sandbox，也没有使用 `group.com.stik.stikdebug`。

## 签名

付费 Apple Developer Program 不是前置条件，本仓库也不采购会员、代签或签名服务。

手机上的开发者模式是系统开关，打开它不等于购买会员。R4S 上的 Python 控制台不安装这个 App，所以那条路径没有这个 App 的 7 天签名。

Xcode 工程是 Automatic，没有填写 `DEVELOPMENT_TEAM`。装到自己的手机时，选择本机免费 Apple ID 的 Personal Team。这不是付费账号才能编译的设置。本程序里没有 Apple ID 或密码输入。

免费描述文件大约 7 天过期，之后需要用 Xcode 重新安装，或由用户自己的侧载工具刷新。本程序不会在到期后自己重新签名，也不承诺免费签名可以一直有效。SideStore 的正常刷新是否适用于本程序，要等真机，这里没有结果。

## 本环境做了什么

主机是 Linux x86_64。`xcodebuild` 不存在，所以 `LanLocation.xcodeproj` 没有编译，界面和 `import idevice` 的文件也没有编译。

Swift 6.0.3 Linux 工具链执行 `swift test --filter CoreTests`：8 项通过，0 失败。测试使用假端口，另有收藏落盘和回环地址判断。它们没有连接 iPhone。

`scripts/fetch-idevice.sh` 用已经下载的官方压缩包完成校验和安装。设备库里能找到 `location_simulation_set` 和 `tunnel_create_rppairing`。这不是 iOS 链接。

个性化镜像清单的 URL 返回 HTTP 200。没有下载 `Image.dmg`，也没有挂载。

`rustc` 1.83.0 在这台机器上存在，但没有 Apple SDK，不能把 idevice 编成 iPhone 用的静态库。Xcode 使用的是官方 XCFramework，不是这里用 cargo 现编的库。
